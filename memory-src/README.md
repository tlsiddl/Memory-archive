# 기억 서재 0.10.21

활성 채팅 요약과 대화 원문을 가져와 줄거리·관계, 챕터, 사건, 발언으로 정리하는 마리나라 개인 확장입니다. 기존 채팅 원문, 기본 요약, LTM 설정은 변경하지 않습니다.

## 설치 및 업데이트

ZIP을 개인 확장으로 가져오고 필요한 전체 페이지 접근 권한을 확인한 뒤 활성화해 주세요. 이전 버전과 중복 실행하지 말고, 가능하면 기존 확장의 업데이트·교체 방식으로 설치해 주세요. 별도 항목으로 설치되었다면 이전 버전에서 방별 JSON 백업을 받은 뒤 새 항목에서 복원하실 수 있습니다.

화면 오른쪽 책 모양 아이콘을 누르면 기억 서재가 열립니다. 모바일에서는 상단 메뉴를 좌우로 이동하실 수 있습니다. 확장의 안내와 오류 문구는 존댓말로 표시합니다. 저장된 이야기와 실제 캐릭터 발언은 원문을 유지합니다.

## 먼저 설정할 내용

설정에서 기억 관리용 모델과 의미 검색 설정이 있는 연결을 선택하고 저장해 주세요. 임베딩 모델·API 키는 마리나라 연결에 저장된 것을 사용합니다.

새 사용자는 수집·가져오기에서 활성 요약 또는 대화 구간을 먼저 가져와 주세요. 필요한 경우 항상 참고할 내용을 정리하고 의미 검색 색인을 갱신한 뒤 ‘이 방에서 기억 사용’을 켜 주세요. 생성 후 검색·주입 확인에서 실제 전달 내용과 서버 응답 수신을 확인하실 수 있습니다.

새 구조가 제대로 작동하는 것을 확인한 뒤 기존 전체 요약의 상시 전달을 직접 조절해 주세요. 확장은 해당 설정을 자동으로 끄지 않습니다.

## 기본 화면

- 기억 보관함: 진행 중 챕터, 사건·발언 수, 최근 챕터와 사건을 보여줍니다.
- 챕터: 겹쳐진 파일 인덱스에서 챕터를 선택하고 사건을 펼쳐 볼 수 있습니다.
- 사건·발언: 인물·대사·사건으로 검색하고 편집·고정·삭제·근거 확인을 할 수 있습니다.
- 항상 참고할 내용: 매 응답에 넣는 두 종류의 요약을 관리합니다.
- 수집·가져오기: 활성 요약 가져오기, 대화 구간 지정, 최근 대화 수집, 색인 관리, 백업을 제공합니다.
- 검색·주입 확인: 마지막 응답에 전달한 기억과 분량을 확인합니다.
- 설정: 채팅방별 연결, 자동 수집, 검색 방식, 각 계층의 예산을 조절합니다.

## ‘항상 참고할 내용’의 뜻

전체 줄거리·관계는 처음부터 이어진 핵심 연표, 현재 관계, 유효한 약속과 미해결 문제를 정리한 요약입니다.

진행 중인 챕터는 현재 장면이 어디까지 진행되었는지 정리한 요약입니다. 완료된 챕터의 사건과 발언은 보관하고 현재 상황에 관련될 때 검색해 전달합니다.

각 항목은 설정에서 켜고 끌 수 있습니다. 설정이 켜져 있으면 매 생성 요청에 해당 요약을 예산 안에서 전달합니다. 개별 사건과 발언은 별도 검색 대상입니다.

## 활성 요약 가져오기

수집·가져오기 → 활성 요약 확인하기에서 현재 채팅방에 켜져 있는 요약만 읽습니다. 가져올 항목을 선택한 뒤 선택한 요약 가져오기를 눌러 주세요.

요약 내용은 확장 기억으로 복사하여 보관합니다. 마리나라의 원래 요약을 이동·삭제·수정하거나 활성 상태를 바꾸지 않습니다. 요약을 다시 가져왔을 때 같은 항목의 내용이 바뀌었으면 이전 스냅샷을 보관하되 검색 대상에서는 최신 내용으로 갱신합니다. 자동 실시간 동기화는 아닙니다.

이 자료는 요약 출처이므로 실제 대사의 원문 확인 표시를 붙이지 않습니다. 원문 인용은 실제 메시지와 대조해야 합니다.

TXT 가져오기는 수집·가져오기 아래 ‘다른 가져오기·백업’에 있습니다. 다른 곳에서 만든 요약을 옮길 때 사용하는 보조 기능입니다.

## 대화 구간 직접 지정

수집·가져오기 → 대화 구간으로 챕터 만들기에서 시작·끝 메시지 번호를 입력해 주세요. 끝 번호를 비우면 마지막 메시지까지 선택합니다. 두 끝 번호를 모두 포함합니다.

사용자와 캐릭터의 메시지는 각각 한 개입니다. 서버의 전체 메시지 번호를 기준으로 하므로 시스템·숨김 메시지가 포함된 채팅에서는 번호 간격과 실제 수집 개수가 다를 수 있습니다. 미리보기의 첫·마지막 메시지와 내용을 확인해 주세요.

선택 구간은 필요한 만큼 이전 페이지를 읽어 수집합니다. 최근 80개 제한은 이 기능에 적용되지 않습니다. 조회 중 메시지 수가 바뀌거나 원문을 모두 읽지 못한 경우 일부만 요약하지 않고 중단합니다. 미리보기 이후 원문이 바뀌어도 다시 확인하도록 안내합니다.

‘이 구간을 챕터로 정리’를 누르면 최대 42,000자 안에서 완전한 메시지 단위로 나누어 정리합니다. 한 메시지 자체가 이 한도를 넘으면 수동 분할·정리가 필요합니다. 완료된 결과는 보관된 챕터로 추가하며 현재 실제 채팅의 줄거리·관계와 진행 중 챕터를 과거 시점으로 바꾸지 않습니다.

묶음마다 진행분을 저장합니다. 중단되거나 오류가 발생했다면 같은 구간과 같은 챕터 이름으로 다시 실행해 저장된 묶음부터 이어갈 수 있습니다. 저장되는 임시 작업은 방별 마지막 한 작업입니다. 원문이나 이름이 바뀌면 새 작업으로 처리합니다.

같은 구간을 다시 정리하면 그 구간의 기존 결과를 교체합니다. 현재 진행으로 지정한 구간 챕터는 마감 후 다시 정리해 주세요. 긴 구간은 모델 호출·비용·대기 시간이 늘어납니다.

## 챕터와 육하원칙

챕터 하나에 여러 사건을 저장할 수 있습니다. 사건 추가에서 누가, 언제, 어디서, 무엇을, 어떻게, 왜, 결과를 입력해 주세요. ‘무엇을’은 필수이며 이유가 불명확하면 미상으로 남깁니다.

사건 하나에 발언을 여러 개 연결할 수 있습니다. 화자, 상대, 작중 시점, 실제 문장, 말·글·생각·대본 구분, 아는 인물, 근거 메시지 ID를 별도로 보관합니다. 근거 ID는 선택 입력입니다.

자동 수집도 같은 구조를 사용합니다. 자동으로 추출한 이유는 원문에 있는 근거 문자열이 함께 확인될 때만 보존하고, 그렇지 않으면 미상으로 처리합니다. 인용 문자열 역시 근거 원문에 그대로 있는지 검사합니다. 이 검사는 문자열 검사이므로 화자·날짜·이유 해석의 완전한 정확성을 보장하지 않습니다.

과거 버전에서 어느 챕터에 속했는지 알 수 없는 사건은 미분류에 보존합니다. 사건 편집에서 챕터를 지정하실 수 있습니다.

## 자동 수집과 검색

기본 자동 수집은 완료 답변 3개마다 다음 생성 요청 전에 실행합니다. 최근 최대 80개 메시지에서 새 대화를 확인하며, 80개보다 많은 대화가 미수집으로 쌓였다면 구간 지정으로 보완해 주세요.

검색은 임베딩과 단어 검색을 결합합니다. 저장된 기억 벡터는 내용이 바뀔 때만 갱신하며, 모델·검색 공간 변경도 확인합니다. 기본 검색 후보는 80개이고 최종 전달 개수에는 고정 제한이 없습니다. 모델 장면 판단을 켜면 후보 중 현재 상황에 필요한 기억과 자연스럽게 먼저 떠올릴 경험을 선택합니다.

선택한 사건에는 연결된 발언과 같은 챕터의 바로 앞·뒤 사건을 추가로 참고합니다. 모두를 무제한 전달하지 않고 토큰 예산 안에서만 전달합니다.

기본 총 예산은 12,000 추정 토큰, 전체 줄거리·관계와 현재 챕터는 각각 최대 2,500 추정 토큰입니다. 정확한 모델 토크나이저가 아닌 문자 종류별 추정치에 여유 배율을 적용합니다. 실제 토큰·요금과 차이가 있으며, 이 예산은 전체 프롬프트가 아닌 확장 기억 자료만 다룹니다.

최초에는 수집·가져오기에서 전체 색인을 만들어 주세요. 이후 새 기억은 생성 전 최대 16개씩 자동 색인합니다. 미색인 기억이 남으면 검색·주입 확인에 표시합니다. 임베딩 호출이 실패하면 단어 검색으로 보완한 사실을 표시합니다. 마리나라의 /api/generate/raw/embeddings 지원이 필요합니다.

장면 판단은 응답마다 추가 모델 호출, 수집 시에는 별도 정리 호출이 발생합니다. 임베딩 검색·색인에도 별도 비용과 시간이 발생합니다. 실제 과거를 먼저 꺼낼지는 기억을 전달받은 본문 모델이 결정합니다.

## 보관과 복구

기억은 서버에 방별로 저장됩니다. 기기를 바꿨다면 새로고침하여 다시 불러와 주세요. 저장 전 버전 충돌을 확인하지만 서버 원자 잠금은 아니므로 같은 방을 여러 기기에서 동시에 생성·편집하지 말아 주세요.

방별 JSON 백업·복원과 최근 4개 내용 변경 되돌리기를 지원합니다. 삭제는 검색에서 제외하는 논리 삭제이며 백업에는 남습니다. 사건을 삭제하면 연결된 발언도 함께 제외합니다. 임베딩 캐시는 재생성 가능한 파생 자료여서 JSON 백업에는 포함하지 않습니다. 복원 후 색인을 갱신해 주세요.

근거 확인은 최근 조회 범위의 원문을 표시합니다. 범위 밖의 원문은 출처 ID로 확인해 주세요. 최근 원문 수정·삭제가 관측되면 관련 기억과 요약을 제외하고 재수집을 안내합니다. 모든 과거 분기·삭제를 상시 추적하지는 않습니다.

책 모양 전체 화면 전환이나 약속별 이행·철회 전용 장부는 별도 기능입니다. 현재 버전은 파일 인덱스형 챕터 화면과 사건·발언 연결을 제공합니다.

## 검증

코어·모의 호스트·DOM 검증과 실제 Chromium의 데스크톱·모바일 화면 검증을 실행했습니다. 활성 요약 필터링, 과거 페이지 순회, 구간 요약·중단 후 재개, 원문 변경 감지, 현재 진행 보존, 사건·인용 연결, 예산, 저장·실패 처리 등을 확인했습니다. 실제 사용자 서버와 연결 제공자 모델의 품질은 설치 후 확인해야 합니다.


## 0.5.1 화면과 제목

챕터 제목은 기억 수집 때 AI가 실제 내용에 맞춰 정합니다. 새 챕터는 정리 대기 상태로 시작합니다. 대화 구간 수집의 이름은 비워 두실 수 있으며, 직접 입력한 이름은 AI가 바꾸지 않습니다. 챕터 이름·요약 편집에서 AI로 제목 정하기를 실행하시면 기존 챕터도 다시 이름 붙일 수 있습니다. 이 기능은 모델을 한 번 호출합니다. 직접 이름을 수정해 저장하면 해당 이름이 유지됩니다.

상단의 달·해 버튼으로 밝은 화면과 어두운 화면을 바꾸실 수 있습니다. 처음에는 기기의 색상 설정을 따르며, 직접 고른 화면은 해당 브라우저에 저장됩니다. 모든 선택 항목은 키보드로도 켜고 끌 수 있는 토글입니다.

항상 참고할 내용은 세로로 넓게 배치한 편집창에서 수정합니다. 글자 수와 추정 토큰 수를 바로 확인하실 수 있으며, 수정 내용은 변경 내용 저장을 눌러 반영해 주세요. 화면 테마를 바꾸거나 메뉴를 오가더라도 같은 방의 저장 전 입력은 유지됩니다. 방을 바꾸거나 확장을 종료하면 저장 전 내용은 초기화됩니다.


## 0.5.1 가독성과 참고 내용 탭

참고할 내용 화면의 전체 줄거리·관계 / 진행 중인 챕터 탭으로 표시할 편집창을 선택합니다. 두 입력은 탭을 바꾸어도 유지되며 변경 내용 저장을 누르면 함께 반영됩니다. 방향키와 Home·End 키로도 탭을 이동하실 수 있습니다. 긴 내용은 편집창 안에서 스크롤합니다.

색상 변수 이름을 확장 전용으로 분리해 마리나라 테마의 색상 변수가 덮어쓰지 않도록 수정했습니다. 밝은 화면과 어두운 화면 모두 기본 글자·안내·입력 힌트의 대비를 높였으며, 버튼은 올림·누름 상태에서 배경 전체가 바뀝니다.


## 0.6.0 채팅방과 턴 수

확장 이름을 기억 서재로 변경했습니다. 내부 저장 키는 유지합니다. 새 항목으로 별도 설치되었다면 이전 확장에서 방별 백업을 내보낸 뒤 복원해 주세요. 기존 항목의 업데이트 방식으로 교체하시면 같은 확장 저장소를 이어서 사용합니다.

상단에는 선택한 채팅방의 실제 이름, 총 턴 수, 원문 전체 메시지 수를 표시합니다. 캐릭터·서술자의 비어 있지 않은 답변 1개를 1턴으로 세며 첫 인사를 포함합니다. 숨김·명령 전용 메시지는 턴에서 제외하고 원문 전체 메시지 개수에는 포함합니다. 따라서 메시지 수를 2로 나눈 값과 다를 수 있습니다. 집계는 전체 원문을 페이지별로 조회하며 모델을 호출하거나 원문을 기억 컨텍스트에 넣지 않습니다. 열기와 새로고침 때 갱신하며 집계 중 원문 개수가 바뀌면 재확인을 안내합니다.

채팅방 이름을 누르면 검색 가능한 전체 채팅방 목록이 열립니다. 방을 선택하면 그 방의 기억을 확인·편집합니다. 실제 마리나라 대화 화면은 이동하지 않습니다. 다른 방을 열람하는 동안 표시를 구분하며, 현재 대화의 기억 열기로 돌아갈 수 있습니다. 각 방의 저장 전 요약과 사건 입력은 확장이 실행 중인 동안 개별 보관됩니다. 본문 생성에는 실제 생성 요청의 채팅방 ID에 해당하는 기억만 전달합니다.

플로팅 버튼은 글자 없는 책갈피 책 아이콘으로 표시합니다. 접근성 이름과 마우스 도움말은 기억 서재로 제공합니다.


## 0.7.0 전체 대화 자동 정리

수집·가져오기에서 전체 대화 자동 정리를 누르시면 범위를 직접 지정하지 않고 첫 메시지부터 마지막 메시지까지 AI가 읽고 여러 챕터로 분류합니다. 챕터 개수·길이는 고정하지 않습니다. 메시지를 나눠 읽는 기술적 배치와 이야기의 챕터 경계는 별개이며, 앞 챕터가 다음 배치로 이어질 수 있습니다. 제목·요약·사건·발언을 함께 추출합니다. 각 챕터에는 원문 메시지 번호 범위와 배정된 메시지 수가 표시됩니다. 숨김·시스템·명령 전용·빈 메시지는 분류에서 제외하므로 원문 전체 개수와 처리 개수가 다를 수 있습니다.

진행률과 생성된 챕터 수를 확인하실 수 있습니다. 중단하거나 실패하면 완료한 배치를 보관하고 같은 버튼으로 이어서 실행합니다. 기존에 처리한 원문이 수정·삭제되었으면 다시 읽습니다. 뒤에 새 메시지만 추가되었으면 저장된 분류에서 이어갑니다. 전체 정리를 반복해도 이전 자동 정리 결과를 교체하며 중복 누적하지 않습니다. 편집한 자동 정리 결과도 재실행하면 다시 만들어지므로 필요한 경우 먼저 JSON 백업을 내보내 주세요. 수동 챕터와 다른 구간 가져오기는 별도로 유지합니다.

현재 진행 챕터가 없는 방에서는 전체 줄거리와 마지막 진행 챕터를 함께 채웁니다. 기존 전체 자동 정리에서 이어진 진행 챕터는 재실행 결과로 갱신합니다. 별도로 진행 중인 수동·실시간 챕터가 있다면 해당 현재 상황은 유지하고 전체 정리 결과는 보관합니다. 분류 누락·중복 배정이 발견되거나 정리 도중 원문이 바뀌면 부분 결과를 본 기억에 합치지 않습니다. 긴 대화에는 여러 모델 호출이 발생합니다.

직접 범위를 지정하는 기능은 접힌 보조 메뉴에서 계속 사용하실 수 있습니다.


## 0.7.1 모델 응답 형식 오류 대응

모델이 JSON 앞뒤에 설명이나 코드 블록을 붙인 경우 완성된 JSON 객체만 읽습니다. 선행 추론 블록은 구분하며, 인용 문자열에 포함된 태그는 변경하지 않습니다. 문자열의 실제 줄바꿈·탭과 마지막 쉼표 같은 명확한 문법 문제만 정규화합니다. 잘린 응답의 닫는 괄호나 빠진 기억 내용은 만들어 채우지 않습니다.

전체·구간 정리 중 응답이 완성되지 않으면 메시지를 생략하지 않고 같은 부분을 더 작은 묶음으로 다시 요청합니다. 성공한 작은 묶음 크기는 이어하기에도 적용됩니다. 한 번의 묶음에서 재시도는 최대 6회이며, 한 메시지도 실패하면 출력 한도를 늘려 한 번 더 시도한 뒤 구체적인 오류를 표시합니다. 원본 내용과 완료한 수집은 유지합니다. 응답 글자 수·요청 출력 한도·제공된 완료 사유를 오류에 표시하고, 모델의 추론이나 원문 응답은 오류 안내에 노출하지 않습니다. 재시도에는 추가 모델 호출이 발생할 수 있습니다.


## 0.7.2 원문 불일치 발언의 분리

자동 수집과 전체·구간 정리에서 원문과 일치하지 않는 인용 하나 때문에 작업 전체를 중단하지 않습니다. 해당 후보를 검색·전달되는 기억에서 제외하고 사건·발언의 원문 확인 대기로 옮깁니다. 정확한 인용과 다른 사건은 그대로 처리합니다. 불일치한 문장이 요약이나 사건 설명에 그대로 반복된 경우에는 발언 원문 확인 대기 표시로 바꿉니다. 원문이 없는 발화자나 날짜를 보정해서 만들어 넣지 않습니다.

확인 대기 항목에서 원문 전체를 읽고, 실제 원문의 연속된 발언으로 수정·등록하거나 후보를 제외하실 수 있습니다. 등록 시 최신 원문을 다시 읽고 저장된 근거와 같은지 확인합니다. 발화자·상대·형태·시점은 모델의 추출이므로 직접 확인해 주세요. 원문이 바뀌었다면 다시 수집해야 합니다. 후보와 원문 미리보기는 백업과 이어하기에 함께 보관됩니다. 전체 정리를 다시 실행하면 해당 자동 정리 결과와 확인 대기 목록도 다시 만들어집니다.


## 0.7.3 발언 자동 복구

새로 수집한 불일치 발언은 수동 확인을 요구하지 않습니다. AI가 해당 근거 원문을 한 번 더 읽고 실제 발언을 찾습니다. 복구 응답의 문장도 원문에 정확히 있는지 프로그램이 다시 대조합니다. 일치하면 자동 등록하며, 못 찾거나 복구 호출이 실패하면 직접 인용만 제외하고 사건 정리를 계속합니다. 불일치 발언이 없는 경우 복구 호출은 발생하지 않습니다.

한 번에 처리한 묶음의 후보들을 함께 확인하므로 발언마다 개별 호출하지 않습니다. 한 복구 묶음은 최대 24개 후보·42,000자 원문이며, 같은 후보를 반복 요청하지 않습니다. 원문이 바뀌었거나 없으면 그 인용은 제외합니다. 새 자동 결과는 수동 확인 목록에 누적하지 않고 복구·제외 개수만 표시합니다. 발화자·시점 등은 모델이 추출한 정보이며, 원문 문자열 대조가 해당 해석까지 보장하지는 않습니다.

이전 버전에서 저장한 대기 후보는 전체 대화 자동 정리를 다시 실행할 때 함께 자동 처리합니다. 복구 실패나 제외가 있어도 다음 사건·챕터 수집은 계속 진행됩니다. 모델이 지어낸 인용을 직접 인용으로 채택하지 않습니다. 복구 호출에는 추가 모델 사용량이 발생할 수 있습니다.


## 0.7.4 사건 연결과 모바일 버튼

모델이 존재하지 않는 사건 참조를 발언에 붙였거나 다른 챕터의 사건에 연결한 경우, 임의의 사건을 만들어 연결하지 않고 발언을 해당 챕터 단위로 보관합니다. 원문 문자열 검사와 자동 복구는 계속 적용합니다. 챕터 상세의 챕터의 발언에서 사건 연결이 없는 발언을 확인하실 수 있습니다. 잘못된 챕터 참조 등 원문 소속을 확인할 수 없는 오류는 계속 검증합니다.

플로팅 버튼을 앱 본문과 분리해 최상위 고정 레이어에 표시합니다. 모바일에서 본문이 다시 그려지거나 변형·스크롤되어도 버튼이 본문과 함께 사라지지 않도록 수정했습니다. 화면 회전과 화면에 실제 보이는 영역의 크기·위치 변화에 맞춰 버튼 위치를 조정합니다. 확장을 업데이트한 뒤 모바일 페이지도 새로고침해 주세요.


## 인물별 기억

인물별 기억 탭에서 NPC와 사용자 캐릭터를 선택해 관련 사건, 주고받은 발언, 관계·약속·사실을 확인하실 수 있습니다. 실제 참여한 인물과 knownBy에 명시된 지식 보유자를 구분합니다. 이 보기는 저장된 사건을 모아 보여주며 새 인물 설정이나 전기를 생성하지 않습니다. 현재 방의 기억만 사용합니다.

새 수집은 people 배열로 관련 인물을 함께 저장합니다. 기존 기억은 기존 기억을 인물별로 정리 버튼을 눌러 분류합니다. 이 작업은 저장된 기억을 나눠 읽고 이름만 붙이며 원문·사건·인용을 변경하지 않습니다. 입력에서 확인되지 않는 이름은 제외합니다. 변경되지 않은 기억은 다시 호출하지 않고, 완료한 묶음은 저장하므로 실패 후 이어서 실행하실 수 있습니다. 이름이 다르게 기록된 별칭은 자동으로 같은 인물이라고 추정해 합치지 않습니다. 사건 편집의 관련 인물 칸에서 직접 수정할 수 있습니다.


## 작중 시간과 시간순 기억

챕터 카드와 상세, 사건, 발언, 인물별 기억에 작중 시점을 표시합니다. 확인되는 날짜와 시·분은 수집할 때 보존하며, 기록되지 않은 시간은 미상으로 표시합니다. 발언 시점이 없지만 관련 사건의 시점이 있으면 발언 시점 미상과 사건 시점을 구분해서 표시합니다.

시간순 기억 탭에서는 연·월·일이 명확한 기록을 날짜·시각순으로 정렬합니다. 정확한 시각이 없는 같은 날짜의 기록은 그 날짜의 시각 확인 기록 뒤에 모아 표시합니다. 상대 시점이나 시점 미상은 별도 구역에서 원문 메시지 순서를 유지합니다. 새 수집은 원문 메시지 순번과 실제 작성 시각도 근거 정보로 보관합니다. 실제 작성 시각을 작중 시간으로 바꾸지는 않습니다. 이전 기억의 누락된 시간을 임의로 복원하지 않으므로 필요한 경우 원문을 다시 수집하거나 사건·발언 편집에서 수정해 주세요.

### 본문 시간과 트래커 연동

본문 머리말의 날짜·시각을 우선 읽습니다. 본문에 시각만 있으면 같은 메시지·활성 스와이프의 과거 트래커 날짜를 함께 전달합니다. 기본 date/time 및 월드 커스텀 필드의 날짜·시간 항목을 지원하며, 회상 시점은 장면 시간으로 강제 변경하지 않습니다. 본문·트래커 근거가 다르면 시간순 기억의 근거 펼치기에 둘 다 표시합니다. 과거 스냅샷이 없거나 서버에서 지원하지 않으면 본문만 사용하며 현재 트래커 날짜나 실제 작성 날짜로 보충하지 않습니다. 개별 메시지 트래커 조회는 최대 네 건씩 처리하며 추가 모델 호출은 발생하지 않습니다. 이름이 자유로운 사용자 정의 트래커의 날짜가 본문에도 없으면 자동 인식되지 않을 수 있습니다.

기존 기억에 없는 인물·시간을 채우려면 기존 기억 인물 정리 또는 대화 전체 자동 정리를 다시 실행해 주세요. 인물 정리는 시간·사건을 다시 추출하지 않습니다.

## 0.7.5 모바일 조작

모바일 닫기와 화면 테마 버튼은 상단 제목 옆에 고정됩니다. 두 버튼 모두 44px 터치 영역을 제공하며, 테마 버튼은 다른 메뉴와 같은 선 아이콘을 사용합니다. 플로팅 책 버튼은 손가락이나 마우스로 드래그해 이동할 수 있습니다. 이동을 끝내도 창이 열리지 않으며, 짧게 누르면 기존처럼 창이 열립니다. 위치는 해당 기기·브라우저에 저장되고 화면 회전·키보드 표시 때 화면 안으로 조정됩니다.

## 0.7.6 정리 중 요청 중단 대응

대화 구간·전체 자동 정리와 기존 인물 분류 요청은 최대 5분까지 기다립니다. 다른 모델 요청은 기존 2분 제한을 유지합니다. 시간 초과, 연결 중단, 직접 중단을 구분해 안내합니다. 전체·구간 정리는 시간 초과나 연결 중단 시 해당 묶음을 더 작게 나눠 자동 재시도합니다. 자동 재시도는 한 번 실행당 최대 두 번이며, 메시지 한 개에서도 중단되면 중지합니다. 이때 완료한 묶음과 축소된 처리 단위를 저장하여 같은 작업을 다시 실행하면 이어집니다. 직접 중단한 경우에는 자동 재시도하지 않습니다. 본문 생성 요청에는 자동 재시도를 적용하지 않습니다.

## 0.7.7 챕터 근거 ID 자동 정리

AI가 같은 챕터의 이전 묶음에서 이미 확인한 메시지를 다시 나열하면 기존 연결을 보존하고 이번 묶음의 새 ID만 추가합니다. 확인되지 않은 ID, 다른 챕터로의 과거 메시지 재배정은 허용하지 않습니다. 전체·구간 정리에서 근거 ID나 챕터 배정이 잘못되면 현재 묶음의 허용 ID를 알려 최대 두 번 자동 재시도하며, 반복 실패 시 더 작은 묶음으로 줄입니다. 현재 묶음의 누락·중복 배정·순서와 발언 원문 검사는 유지합니다. 끝내 실패하면 완료한 묶음은 저장하고 멈춥니다.

## 0.7.8 처리량 자동 회복

이전 실패로 처리량이 1개까지 줄어든 상태도 완료한 지점부터 이어집니다. 세 묶음이 연속 성공하면 다음 처리 한도를 두 배씩 늘리며 최대 32개·원문 42,000자 제한을 유지합니다. 현재 실행에서 큰 묶음이 실패하면 축소된 한도를 상한으로 삼아 같은 크기의 실패를 반복하지 않습니다. 다시 실행할 때는 연속 성공에 따라 확대를 다시 시도할 수 있습니다. 진행 화면에 이번 묶음 크기와 다음 처리 한도를 표시합니다. 처리 묶음과 챕터 경계는 별개이며, 기존 챕터를 임의로 다시 나누지는 않습니다.

## 0.7.9 기억을 유지하는 저장 공간 최적화

기존 gzip에 더해 반복되는 객체·문자열·되돌리기 상태를 공유 구조로 압축합니다. 두 저장 형식의 실제 크기를 비교하여 작은 쪽을 사용합니다. 읽을 때는 원래 데이터와 독립된 되돌리기 상태로 복원합니다. 사건·발언·시간·인물·근거·사용자 되돌리기는 삭제하지 않습니다. 검색 색인은 숫자를 반올림하지 않고 64비트 이진 값으로 저장하는 방식과 기존 저장 방식 중 작은 쪽을 선택합니다.

수집·가져오기 → 저장 공간에서 사용량 확인 또는 이 방 저장 공간 최적화를 실행하실 수 있습니다. 모델 호출 없이 현재 방의 기억·색인·전체/구간 작업 저장 상태만 다시 압축합니다. 작업 저장 상태의 내부 undo는 사용자 되돌리기가 아닌 처리 과정 복사본이므로 비웁니다. 처리한 메시지·진행 지점·추출 내용은 유지합니다. 다른 방은 변경하지 않습니다. 새 정리에서도 내부 복사본을 누적 저장하지 않습니다.

이전 평문·gzip 자료는 그대로 읽을 수 있습니다. 새 압축 형식은 구버전에서 열리지 않을 수 있으므로 사용하는 모든 기기에서 확장을 업데이트해 주세요. 백업 JSON은 기존처럼 일반 JSON으로 내보냅니다. 압축해도 저장 한도는 유한하며 실제 절감률은 기억 내용·색인·작업 상태에 따라 달라집니다. 사용량은 확장 전체 JSON 크기를 표시하며 서버 디스크 사용량과 다릅니다.

## 0.8.0 요청 횟수 제한 대기와 자동 재개

서버가 보내는 RateLimit-Limit을 읽어 일반 조회·저장과 생성/임베딩 요청의 시작 간격을 조절합니다. HTTP 429 응답에서는 Retry-After, RateLimit-Reset 순서로 대기 시간을 읽고, 정보가 없으면 약 1분 기다립니다. 대기 시간을 화면에 표시한 뒤 동일한 기억 관리 요청을 최대 세 번 재시도합니다. 5분이 넘는 대기 지시나 반복 제한은 진행 내용을 유지하고 중지합니다. 대기 중에도 중단·확장 종료를 처리합니다. 본문 생성 요청의 자동 재전송은 하지 않습니다.

트래커 조회를 포함한 확장 API와 저장소 요청에 적용하며, 다른 확장·브라우저 탭·사용자가 함께 쓰는 서버 한도를 바꾸지는 않습니다. 다른 확장에서 호출이 계속되면 제한이 반복될 수 있습니다.

## 0.8.1 기본 10개 메시지 묶음 분석

전체·구간 정리는 기본 10개 메시지를 하나의 모델 입력으로 보내 사건·발언·시간을 함께 대조합니다. 설정의 한 번에 정리할 메시지 수에서 1~32개로 조절하실 수 있습니다. 원문 42,000자 제한 때문에 긴 메시지는 더 작은 묶음으로 처리될 수 있으며 마지막 묶음은 남은 수만큼 처리합니다. 잘못된 발언의 별도 자동 복구 호출은 유지합니다.

이전 실행에서 실패로 줄어든 1개 처리 단위는 새 실행에 강제로 물려받지 않습니다. 완료한 메시지와 챕터는 이어받고, 처리 단위는 현재 설정값으로 시작합니다. 현재 실행 도중 실패하면 축소하고 연속 성공 시 설정값까지 회복합니다.

대화 범위를 읽거나 마지막에 원문 변경을 확인할 때는 개별 트래커 요청을 하지 않습니다. 실제 분석할 묶음만 시간 근거를 보강하며, 본문에 날짜와 시·분이 명확하면 본문을 바로 사용합니다. 본문에 날짜나 시각이 부족한 경우에만 해당 메시지 트래커를 조회합니다. 트래커를 실제 조회한 경우에만 본문·트래커 차이를 확인할 수 있습니다. 이 변경은 기존에 저장된 챕터를 자동으로 다시 분할하지 않습니다.

## 0.8.2 고정 메시지 묶음

설정한 10개 메시지를 한 묶음으로 유지합니다. 마지막 남은 메시지는 남은 개수만 처리합니다. 이전의 42,000자 기준 자동 분할과 오류 후 절반 축소를 제거했습니다. 입력 원문을 자르거나 생략하지 않으며, 원문 합계 200,000자를 넘으면 개수를 임의로 바꾸지 않고 안내 후 멈춥니다.

형식·근거·연결 오류는 같은 메시지 묶음으로 최대 두 번 재시도합니다. 출력이 잘린 경우에는 다음 시도에서 요청 출력 한도를 높이되 메시지 수는 유지합니다. 계속 실패하면 완료한 묶음과 진행 지점을 보관하고 원인을 표시합니다. 필요하면 사용자가 묶음 크기나 모델 설정을 직접 바꿀 수 있습니다. 각 메시지의 사건·발언·시간 추출 및 원문 검사는 유지합니다.

## 0.8.3 묶음 응답의 중복 출력 축소와 형식 수정 요청

전체·구간 분석은 고정 메시지 묶음을 유지하면서 간결한 출력 계약을 사용합니다. 현재 챕터 요약은 episodes.summary에 한 번만 받고, 중복 episode 필드는 앱에서 같은 내용으로 복원합니다. 줄거리 변화가 없으면 story를 생략하고 기존 내용을 유지합니다. 사건 text가 details.what과 같을 때만 동일 문장으로 복원하며, 발언의 중복 설명은 화자 표시로 대체할 수 있습니다. 발언 원문·시점·근거 ID·사건 내용은 별도로 검증합니다.

JSON 형식 실패 시 이전과 동일한 요청만 반복하지 않고, 실패 사유와 더 간결한 출력 지침을 다음 요청에 전달합니다. 원문 메시지 수는 줄이지 않으며, 잘린 JSON을 임의로 닫거나 미완성 발언을 만들어 저장하지 않습니다. 모델이 실제로 지침을 지키지 않거나 계속 완성된 응답을 주지 않으면 완료한 지점을 보관하고 중지합니다.

정리가 최종 실패하면 수집·가져오기에 오류 진단 내려받기가 표시됩니다. 마지막 실패 모델의 최종 응답·처리 메시지 ID·완료 사유·요청 한도·출력 지침을 현재 화면 메모리에만 보관하며 기억 저장소에는 추가하지 않습니다. API 키·요청 인증 헤더·별도 추론 필드는 수집하지 않습니다. 새로고침하면 사라지고 같은 묶음의 정상 응답을 받으면 해제됩니다.

## v0.8.6 — 실제 진단 응답의 compact fact·인용 근거 누락 대응
- v0.8.5 진단에서 fact가 text 대신 details.what만 반환되고 quote 하나에 sourceIds가 누락되어 전체 묶음이 실패하는 조합을 확인했습니다. compact 변환을 사건뿐 아니라 details.what이 명시된 기억에 적용합니다. 사실 기억의 details(방법·결과·시점·장소 등)도 보존합니다.

## v0.9.0 — 상세 추출 / 독립 원문 대조 / 전체 챕터 구분

기본 전체 정리를 세 단계로 분리했습니다. 설정의 ‘상세 추출·원문 대조·챕터 구분’이 기본으로 켜집니다.

1. 설정한 고정 묶음(기본 원문 10개)을 함께 읽어 상세 사건·양쪽의 중요한 발언·인물 특성·약속·조건·수치·방법·결과를 추출합니다. 챕터 구분은 이 단계에서 하지 않습니다. 직전 원문 두 개를 문맥 참고용으로 주되 새 근거 ID로 섞지 않습니다.
2. 별도 모델 요청에서 같은 원문과 초안을 다시 대조합니다. 빠진 내용과 잘못 연결한 주체/과정/조건을 수정하고 최종 기억 전체를 반환합니다. 각 메시지마다 보존한 기억 또는 지속 기억이 없는 구체적 이유를 기록합니다. 목록의 누락·중복·존재하지 않는 기억 연결을 검사합니다. 이 검사는 의미상 모든 사실이 보존됐다는 보증은 아닙니다.
3. 추출·대조가 완료된 사건들을 모아서 챕터 전용 요청으로 구분합니다. 연결된 사건과 발언의 원문 범위를 합친 최소 구간을 만들고 최대 40개 구간씩 읽습니다. 이는 챕터 수나 원문 추출 묶음 크기를 제한하는 값이 아닙니다. 창 사이에서는 직전 챕터의 연속 여부를 판단합니다. 중심 과제·독립된 장면·시간·장소·참여자의 의미 있는 전환을 고려하며, 전체 이야기가 끝나야만 챕터를 나누는 규칙을 제거했습니다. 개수를 맞추려고 사건이나 챕터를 만들지 않습니다. 기억 ID와 원문 인용은 유지합니다.

### 이어하기와 기존 결과
- 새 작업은 `qualityDraft`에 별도로 저장합니다. 최초 실행에는 기존 방식의 빈약한 추출을 원문 대조 완료로 간주하지 않고 처음부터 새 방식으로 읽습니다. 완료하기 전까지 현재 기억 결과는 교체하지 않습니다.
- 추출 성공 직후 초안을 저장합니다. 대조 실패 시 같은 초안을 재사용하며, 대조 완료 묶음은 다시 추출하지 않습니다. 챕터 단계에서 실패해도 추출/대조를 반복하지 않습니다. 원문이 바뀌면 근거 해시를 검사하고 재정리합니다.
- 전체 정리가 완료되면 기존 전체 정리 결과를 교체하고 마지막 챕터를 실제 현재 흐름으로 지정합니다. 선택 범위 정리의 기존 동작은 유지합니다.
- ‘전체 대화 자동 정리’는 새 작업의 이어하기이고, ‘원문부터 세부 기억 다시 정리’는 진행분도 무시하고 재분석하는 별도 버튼입니다.
- 이 방 전체 비우기와 저장 공간 최적화에 새 임시 기록도 포함됩니다. 원문 채팅은 변경하지 않습니다.

### 이름과 시간
- 원문 메시지의 명시된 인물 이름이 한 명으로 확인되면 역할 표기를 연결합니다. 확인되지 않으면 설정의 ‘사용자 캐릭터 이름’과 ‘주요 상대 캐릭터 이름’을 입력할 수 있습니다. 주변 대사에서 이름을 추측하지 않습니다. 여러 상대가 있는 경우 상대 이름 칸은 비워 둘 수 있습니다.
- user/assistant/템플릿 역할은 확인된 이름 또는 이름 미확인 역할 설명으로 바꾸며, 정확한 인용 원문과 이유의 원문 근거 문자열은 바꾸지 않습니다. 이름 미확인 역할을 인물 탭으로 새로 등록하지 않습니다.
- 작중 헤더와 해당 메시지의 시간 근거를 유지하고 실제 createdAt은 추출/대조 모델의 원문 자료에서 제외합니다.

### 호출 및 검증
- 상세 모드는 보통 원문 묶음당 추출 1회 + 원문 대조 1회이며, 완료 후 챕터 구분 호출이 추가됩니다. 형식 수정이나 인용 복구가 필요하면 추가 요청이 발생합니다. 이전 방식보다 시간과 사용량이 늘 수 있습니다. 최근 대화 수집도 상세 모드에서는 추출과 대조를 분리합니다.
- 모의 호스트 회귀 테스트 118개와 브라우저 검사를 통과했습니다. 독립 단계의 수정 결과 반영, 10개 고정 묶음, 메시지 대조 목록 검사, 추출/대조/챕터 단계 이어하기, 사건-발언 연결 보존, 이름 치환과 정확한 인용 보존, 기존 UI·삭제·시간·저장 동작을 검사했습니다.
- 실제 Gemini 등 사용자 연결의 추출 품질을 재현해 보장하는 검증은 아닙니다. 최종 의미 품질은 원문과 사용 모델의 판단에 따라 달라지며, 각 단계의 실패 응답은 오류 진단에서 확인할 수 있습니다.

## v0.9.1 — 실제 원문 대조 진단의 연결표 불일치와 누락 보완
- 제공된 v0.9.0 진단에서 대조표의 기억 ref가 해당 기억의 sourceIds와 다르게 연결되고, captured라고 표시한 두 메시지는 실제로 어떤 기억의 근거에도 포함되지 않은 것을 확인했습니다.
- 대조표의 memoryRefs는 모델에게 중복 계산을 맡기지 않고 최종 기억의 sourceIds에서 계산합니다. 기존에 반환된 표가 잘못되어도 기억 내용과 실제 sourceIds를 바꾸지 않고 연결표만 맞춥니다. 잘못 보고된 원래 ref는 대조 메타데이터에 남깁니다.
- captured인데 실제 근거 기억이 없는 메시지는 완료 처리하지 않습니다. 같은 원문 묶음을 문맥으로 주고 누락 메시지만 별도 요청으로 보완합니다. 기존 기억을 수정·삭제·축약하거나 ID만 덧붙이는 방식은 허용하지 않고, 새 기억을 추가합니다.
- 보완된 모든 sourceId에는 실제 해당 원문의 연속 문자열 근거가 필요합니다. 각 누락 메시지의 보완 판단에도 정확한 원문 근거를 확인합니다. 존재하지 않는 ID, 기존 ref 덮어쓰기, 근거 문자열 조작, 보완 후에도 captured인데 기억이 없는 경우는 저장하지 않습니다. 정말 지속 내용이 없는 경우에만 원문 근거와 이유를 붙여 context_only로 처리합니다. 이 검사는 모든 의미적 사실의 완전한 보존을 보장하지는 않습니다.
- 대조 결과도 임시 저장합니다. 누락 보완에서 실패하면 다음 실행에서 추출·대조를 반복하지 않고 보완 단계부터 이어갑니다. 10개 고정 묶음·전체 챕터 별도 구분·기존 기억 보존은 유지합니다. v0.9.0의 qualityDraft와 호환됩니다.
- 회귀 테스트 123개 통과. 실제 제공 진단의 연결표를 기억/근거 변경 없이 정리하여 미보존 메시지 두 개를 식별하는 로컬 재현을 확인했습니다. 추가 사실의 의미 정확도는 원문 대조 모델 판단에 의존하며, 제공된 진단에는 원문이 없어 실제 인용/보완 내용의 정확도를 검증한 것은 아닙니다.

## v0.9.2 — 누락 보완 형식 정리와 부분 진행 보존
- v0.9.1 진단에서 보완 응답이 대상 일부만 반환하고 sourceEvidence를 생략한 사례를 확인했습니다. 보완 프롬프트에 전체 추출 스키마가 함께 들어 있던 구성을 없애고, additions/coverageUpdates 한 가지 양식과 정확한 sourceEvidence 예시로 분리했습니다. 기존 whyEvidence가 sourceEvidence를 대체하지 않는 점을 명시했습니다.

- 모의 호스트 회귀 테스트 126개 통과. 부분 보완 후 미해결 항목 유지, 해결 수 감소 검사, 중간 실패 이후 이어하기, 기존 근거 검사·연결표·고정 묶음·UI 동작을 검증했습니다. 실제 사용자 모델이 원문에서 모든 내용을 정확히 보존한다는 보증은 아닙니다.

- 이미 수집한 챕터는 ‘디테일·대화 보완’으로 보완하실 수 있습니다. 현재 챕터, 앞 챕터, 직접 연결된 기억의 실제 원문을 현재 챕터 끝까지 다시 읽습니다. 기존 사건과 요약은 덮어쓰지 않고 사실과 양쪽 문답을 추가합니다. 별도 모델 호출이 발생합니다. 전체 삭제·재수집은 필요하지 않습니다.
- 새 상세 수집·대조 프롬프트도 구체적인 기간·조건을 사실로 보존하고 양쪽의 질문·응답을 수집하도록 확장했습니다. 기존 완료 구간이나 과거 결과가 업데이트만으로 자동 재추출되지는 않습니다.
- 관련 챕터 링크는 실제 기억 연결과 챕터 사실의 원문 근거로 표시됩니다. 반대편 챕터에서도 참조를 확인할 수 있습니다. 이전·다음 챕터 이동은 내용 연결과 구분합니다.
- 챕터 사건은 원문 순서로 표시합니다. 이어지는 사건 묶음이 떨어진 사건을 앞으로 끌어오지 않도록 했습니다. 타임라인의 작중 날짜 정렬은 유지합니다.
- 보완 발언은 실제 제공 문단 번호, 인용 문자열, 사건 문답 범위를 검증합니다. 직접 편집한 사건과 삭제한 같은 발언을 자동으로 대체·복구하지 않습니다. 동시 수정이나 원문 변경 시 저장을 중단하며 기존 기억은 유지합니다.
- 새 보완은 한 번에 최대 200,000자 원문까지 대조합니다. 그보다 크면 임의로 원문을 잘라내지 않고 안내합니다. 모델이 사실·발언을 얼마나 충실하게 추출하는지는 실제 연결 모델에서도 확인해 주셔야 합니다.


### v0.10.5 — 다음 묶음 사건이 과거 발언 참조로 처리되던 오류 수정

- 현재 사건과 이어지는 실제 후속 응답은 기존처럼 참고 발언으로 유지합니다. 현재·후속 원문이 함께 있는 사건은 이 분리 대상이 아닙니다. 입력에 없는 ID나 과거 원문만 근거로 한 사건은 자동으로 통과시키지 않습니다.

- 미완료 구간의 누락 원문 보완과 다음 묶음 수집은 유지합니다. 업데이트 후 중단된 수집 작업을 같은 버튼으로 이어서 실행하실 수 있습니다. 전체 기억 삭제는 필요하지 않습니다.

### v0.10.7 — 중복 사건 통합과 완전한 핵심 문답 대조

- 원문에 여러 줄로 이어진 이름표 대사/독립된 유저 인용을 후보로 표시합니다. 원래 CRLF/LF 줄바꿈과 문자열을 유지하며, 서로 떨어진 발언을 이어 붙이지 않습니다. 화자 미확정 후보는 계속 모델의 원문 대조가 필요합니다.
- ‘디테일·대화 보완’은 짧은 발췌만으로 발언 후보 전체를 보존했다고 처리하지 않습니다. 핵심 문답은 실제 양쪽 발언 전체를 각각 저장하도록 요청합니다. 제외 후보는 단순 반복·인사/대사 아님/화자 미확정 등의 구체적 사유가 있어야 하며, 챕터에서 제외 사유를 확인할 수 있습니다. 실제 대사가 없는 사건을 위해 인용을 만들지 않습니다.
- 같은 이송 연락과 보호자 대응처럼 유저와 캐릭터가 같은 사건을 중복 서술한 연속 기록은 원문을 대조해 통합합니다. 서로 다른 장면은 유지합니다. 모든 소속 사건의 실제 원문 문단이 있어야 하며 수동 편집·삭제·원문 수정·챕터가 다른 사건은 자동 통합하지 않습니다.
- 통합 전 기록은 사건 안의 ‘통합 전 기록 확인’에 보관합니다. 기존 되돌리기도 유지합니다. 발언의 연결, 외부 기억 링크, 예전 사건 ID 별칭과 원문 근거를 옮겨 통합 후에도 탐색할 수 있습니다. 검색·주입에는 통합된 현재 사건이 사용됩니다.
- 기존 자동 인용이 한 발언의 일부라면, 동일 사건·화자·형태·원문에 속하는 완전한 발언으로 확장하고 이전 인용도 이력에 남깁니다. 직접 편집한 인용은 덮어쓰지 않습니다.
- 기존 내용은 업데이트만으로 자동 변경되지 않습니다. 문제 챕터의 ‘디테일·대화 보완’ 또는 사건의 ‘이 챕터의 발언·중복 정리’를 사용해 주세요. 두 버튼은 해당 챕터 전체를 원문으로 대조하며 모델 호출이 발생합니다. 전체 삭제·재수집은 필요하지 않습니다.
- 새 상세 수집의 대조 지침도 동일 사건 중복 생성 방지와 온전한 핵심 문답 보존을 강화했습니다. 다만 원문을 읽는 모델의 의미 판단·화자 판단과 실제 추출 품질을 자동으로 보증하는 것은 아닙니다.


### v0.10.8 — 자동 발언·사건 대조와 기존 발언 연결 교정

- 새 상세 수집에서 원문 대조·누락 보완 뒤, 실제 발언 후보나 발언 기록이 있는 묶음은 ‘발언·사건 대조’를 자동으로 거칩니다. 사건 목록과 발언을 따로 대조하고 실제 문단 번호로 대사와 소속 사건 양쪽 근거를 선택합니다. 핵심 질문·요구·응답·약속은 발언 전체를 각각 보존하도록 요청합니다. 실제 대사 없는 행동 사건에 인용을 만들지 않습니다.

- 원문 문단 근거를 확인한 실제 교차 턴 연결은 사용자→캐릭터 턴 경계만으로 다시 해제하지 않습니다. 반대로 실제 사건 근거가 없는 연결 교정은 통과시키지 않습니다. 여러 문단에 걸친 연속 인용도 모든 해당 문단이 선택되었으면 그대로 보존합니다.
- 이미 저장된 잘못 연결된 발언과 챕터 발언은 ‘발언 보강·사건 연결’ 또는 해당 챕터 ‘디테일·대화 보완’으로 교정하실 수 있습니다. 같은 원문·화자의 같은 발언을 새로 복제하지 않고 실제 사건으로 옮기며 이전 연결/설명 이력을 보관합니다. 수동 편집 인용은 유지합니다.
- 기존 방 전체는 사건·발언 화면의 ‘발언 보강·사건 연결’을 실행해 주세요. 이전 버전의 완료 표시는 이번 연결 검사를 건너뛰지 않습니다. 새 검사 완료 후에는 기존처럼 이어하기/중복 호출 방지가 적용됩니다. 전체 삭제·재수집은 필요하지 않습니다.
- 자동 발언 대조는 묶음마다 모델 호출을 추가하므로 상세 수집 시간과 비용이 늘 수 있습니다. 실패 시 완료된 추출·원문 대조 진행을 보관하며, 같은 수집 버튼으로 발언 대조부터 이어갑니다. 기존 데이터와 설정은 초기화하지 않습니다.
- 정확한 발언 시점이 없는 경우 소속 사건의 시점과 구분해서 표시하며 실제 작성 시간을 작중 시간으로 대신 쓰지 않습니다. 문단/문자열 검사 통과가 모델의 의미 판단까지 완벽하다는 보장은 아닙니다.

### v0.10.10 — HTML 말풍선의 실제 대사 검증

- 모델에 원본과 보이는 글자를 함께 제공하여 스타일·이름표·시각을 대사와 구분하도록 안내합니다. 문자/앱 메시지는 written으로 분류하도록 지침을 보강했습니다. 표시 형태만으로 발화자나 매체를 강제로 바꾸지 않습니다.

- 기존 업데이트 방식으로 교체한 뒤 실패한 수집 동작을 다시 실행해 주세요. 임시 진행 정보가 있으면 실패한 단계부터 이어갑니다. 기억 전체 삭제는 필요하지 않습니다.
- 이 처리는 임의의 웹페이지 렌더러가 아닙니다. 해석하지 못하는 HTML·미지원 엔티티/레이아웃은 추측으로 통과시키지 않습니다.


### v0.10.11 — 사건 근거 번호 안내와 일괄 재대조

- 발언 출처와 사건 근거는 별개입니다. 발언의 응답 메시지가 사건의 sourceIds 밖에 있더라도, 해당 문답을 실제로 뒷받침하는 사건 문단을 확인하여 연결할 수 있습니다.
- 발언 대조 입력에 각 사건의 allowedEventSourceSegmentNumbers와 각 문단의 eventNumbers를 함께 제공합니다. 사건 의미와 원문을 읽어 선택하며 발언 출처 번호를 사건 근거에 그대로 복사하지 않도록 안내합니다.
- 잘못된 사건 근거를 한 번에 모아 재대조합니다. 오류 JSON/재시도에는 발언 번호·선택한 사건·선택 문단·그 사건에서 허용되는 실제 근거 문단을 담습니다. 동일 사건의 원문은 공통 근거 목록으로 한 번만 전달합니다.
- 검증을 우회하거나 자동으로 첫 문단/다른 사건을 선택하지 않습니다. 사건 출처를 늘리거나 발언을 삭제하지 않으며, 모델이 소속을 확인할 수 없다고 명시한 발언은 기존 방식대로 미연결 상태로 보존합니다.
- 기존 기억·설정·HTML 인용 검사·단계별 이어하기를 유지합니다. 업데이트 후 같은 수집 동작을 다시 실행하시면 진행 정보가 있을 때 실패한 발언 단계부터 이어갑니다.


### v0.10.12 — 실제 문답 근거 인정과 대사·지문 분리

- 자동 발언 대조에서 사건의 sourceIds에 응답 메시지가 빠져 있어도, 실제로 제공된 같은 턴의 문답 또는 바로 직전 질문에 대한 유저 응답임을 원문 순서·메시지 역할·실제 인용·선택 문단으로 검증할 수 있으면 문답 근거로 연결합니다. 의미상 사건 선택은 모델의 eventNumber/linkReason을 사용하며 앱이 임의로 다른 사건에 배정하지 않습니다.
- 사건 sourceIds를 자동으로 늘리거나 아무 문단을 근거로 붙이지 않습니다. 별도의 conversationEvidence와 상대 원문 해시를 남기고, 근거 상대 메시지가 바뀌면 발언도 재검토 상태로 바뀝니다. 원문이 없거나 순서가 끊긴 연결은 거부합니다.
- 따옴표로 구분된 실제 대사 한 개 뒤에 지문이 붙어 spoken으로 반환된 경우, 원문 발언 후보와 정확히 대조해 대사와 지문을 분리합니다. 지문은 삭제하지 않고 quoteContext와 감사 이력에 남깁니다. 화면에는 ‘함께 기록된 지문·내면’으로 구분하며 검색/주입에도 별도 맥락으로 전달합니다.
- 체질이나 증상 설명을 원문에 없는 진단으로 확대하지 않도록 지침을 보강했습니다. 모델의 의미 해석 자체를 자동으로 교정한다고 보장하지는 않습니다.
- 업데이트 후 멈춘 수집을 같은 동작으로 이어가실 수 있습니다. 기존 기억 삭제나 전체 재수집은 필요하지 않습니다.


### v0.10.13 — 확인된 대사 출처로 사건 근거 교정

- 실제 대사 문단이 모델이 선택한 사건의 sourceIds에 속하고 인용 전체가 정확히 확인되면, 사건 근거 번호가 누락되거나 잘못 반환되어도 해당 대사 문단을 근거로 확인합니다. 사건 번호 1을 문단 번호 1로 혼동해도 이미 확인된 원문을 다시 고르는 모델 호출은 필요하지 않습니다.
- 모델이 선택한 사건·실제 대사·화자·시점은 바꾸지 않습니다. 임의의 첫 문단이나 과거 참고 문단을 붙이지 않으며 기존 사건 출처도 늘리지 않습니다. 잘못 반환한 번호와 교정한 실제 근거는 감사 이력에 남습니다.
- 원문에 없는 대사, 대사가 확인되지 않는 출처, 다른 사건의 문단은 이 처리로 통과하지 않습니다. 같은 턴 문답 검증·대사와 지문 분리·HTML 인용 검사도 유지합니다.
- 업데이트 후 같은 수집 동작으로 이어가실 수 있습니다. 임시 진행 정보가 남아 있으면 실패한 발언 단계부터 다시 진행합니다. 기억 전체 삭제는 필요하지 않습니다.


### v0.10.14 — 대사를 재작성하지 않고 원문 후보로 선택

- 자동 발언·사건 대조에서 이미 확인된 대사는 candidateNumber로 선택합니다. 모델이 quote를 다시 쓰지 않아도 앱이 해당 원문 전체와 출처 문단을 가져옵니다. 후보에 없는 발언은 기존처럼 정확한 quote와 실제 문단으로 반환할 수 있습니다.
- 기존 형식으로 반환된 대사가 원문 어디에도 없더라도, 선택한 실제 문단에 해당 화자의 명시된 발언이 단 하나로 확인되면 그 원문 발언을 가져옵니다. 문장 유사도나 오타 추정은 사용하지 않습니다. 후보가 여럿이거나 화자가 다르면 자동 선택하지 않습니다.
- 원문이 다른 곳에 정확히 존재하는 경우에는 기존의 유일한 출처 교정을 우선합니다. 후보 번호와 출처 문단이 충돌하거나 없는 후보 번호를 보고하면 검증 오류로 재대조합니다.
- 모델이 다시 쓴 문장/출처와 실제 선택한 원문을 감사 이력에 남깁니다. 일반 기억과 검색·주입에는 검증된 실제 대사를 저장하며, 원문 자체나 기존 기억을 수정하지 않습니다.
- 업데이트 후 같은 수집 동작으로 이어가실 수 있습니다. 임시 진행 정보가 남아 있으면 실패한 발언 단계부터 진행합니다. 기억 삭제나 전체 재수집은 필요하지 않습니다.

## v0.10.15 발언 추가 대조

대화 원문을 읽는 기존 메시지 묶음 범위는 유지합니다. 그 안의 발언 후보는 고정 번호로 최대 16개씩 사건에 배정하고, 검증된 배정을 임시 작업에 저장합니다. 일부만 반환되면 남은 후보만 추가로 요청합니다. 같은 통화나 업무 일정이라는 이유로 서로 다른 실제 발언을 중복/불필요 대사로 제외하지 않습니다. 대사 아님·화자 미확정 분류와 그 사유는 기존처럼 감사 이력에 남습니다.

진행이 없는 응답은 원문 근거와 함께 재대조하며, 반복 횟수 한도에 도달하면 미완료 상태로 멈춥니다. 같은 작업으로 이어서 실행하시면 검증된 부분을 보존하고 남은 발언부터 계속합니다. 중간 결과를 완료된 기억으로 교체하지 않습니다. 발언이 많은 묶음은 배정 요청이 여러 번 필요하므로 실제 소요 시간과 비용은 모델 응답에 따라 달라집니다. 원문·화자·사건 근거 검사는 유지됩니다.

## v0.10.16 항목별 발언 대조

후보 번호로 선택한 발언 중 일부의 화자나 근거가 잘못되면 해당 후보를 미확인으로 남기고, 같은 응답의 정상 후보는 검증 후 임시 작업에 보존합니다. 문제 후보 번호·문제 필드·실제 원문을 다음 대조에 전달합니다. 잘못된 제안과 오류는 감사 이력에 남으며, 재대조나 동일 작업 재개 시 정상 후보를 반복 배정하지 않습니다. 확인되지 않은 화자를 사건 주체로 바꾸거나 오류 항목을 완료 처리하지 않습니다. 실제 이름이 확인되지 않으면 그 사실과 사유를 기록합니다. unknown은 허용된 발언 형태이므로 자동으로 spoken으로 바꾸지 않습니다.

## v0.10.17 누적 발언의 출처 보존

이미 검증된 짧은 발언이 여러 원문에 근거를 두고 있으면, 그중 한 원문의 긴 발언을 추가할 때 기존의 다른 출처를 제거하지 않습니다. 새 발언을 별도로 검증해 보존합니다. 누락 개수가 같은지만 보지 않고 어떤 후보가 새로 확인되었는지 판단하며, 이어서 실행할 때 저장된 발언 기록으로 진행 상태를 다시 계산합니다. 실제 원문·화자·사건 근거 검사는 그대로 유지합니다.

## v0.10.18 오류 JSON 접근

발언 배정 횟수 제한처럼 모델 응답 검사 밖에서 발생한 오류도 진단 JSON으로 남습니다. 확인한 발언 수·남은 후보·실제 처리 구간·같은 작업으로 재개 가능한지 확인할 수 있습니다. 오류 JSON 복사와 파일 내려받기는 탭 상단에서도 사용할 수 있습니다. 자동 복사가 차단되면 현재 탭에 직접 선택할 수 있는 읽기 전용 입력창이 표시됩니다.

앱 내부 오류에 함께 담긴 직전 모델 응답은 참고 자료로 표시하며, 그 응답 자체가 오류였다는 의미는 아닙니다. 진단은 현재 세션에만 보관하고 기억 저장소에 추가하지 않습니다. 검토 횟수 제한·기존 이어하기·기억 보존 방식은 유지합니다.

## v0.10.19 남은 후보 최종 대조

정상적으로 발언을 확인해 온 묶음에서 일반 검토 횟수에 도달했지만 미확인 후보가 16개 이하로 남았으면, 해당 후보만 하나씩 최종 대조합니다. 추가 요청은 최종 대조를 시작할 때 남은 후보 개수만큼만 허용합니다. 예를 들어 63개 중 62개 확인 후 57번 하나가 남으면 그 번호만 한 번 더 확인합니다. 원문 메시지 묶음·실제 화자·인용·사건 근거 검증은 유지하며, 진전 없는 응답은 기존 재시도 규칙으로 중단합니다. 마지막 후보를 제외하여 완료 처리하지 않습니다.

## v0.10.20 서로 다른 화자와 기록 ID 보존

같은 메시지 안의 짧은 대답과 그 문장으로 시작하는 다른 사람의 긴 발언을 병합할 때, 이미 검증한 화자가 다른 기록은 서로 덮어쓰지 않습니다. 이전 작업에서 다른 발언이 기존 기록 ID를 사용하고 있으면 기존 기록을 보존하고 새 발언에 겹치지 않는 ID를 부여합니다. 새 발언을 확인하면서 이전 발언이 다시 누락되는 경우에는 저장 전 검사에서 멈추고 구체적인 후보 번호를 진단으로 남깁니다. 체크포인트를 이어서 실행할 때도 남은 후보의 최종 대조를 지원합니다.

## v0.10.21 대사와 사건의 별도 근거 선택

발언이 앞 메시지에 있고 소속 사건의 근거가 뒤 메시지에 있을 때는 대사 문단과 사건 문단을 각각 확인합니다. 일반 대조가 사건 근거 문단을 지정하지 못해 반복 실패하면, 해당 발언만 보존한 채 실제 사건의 문단 번호를 별도로 선택합니다. 인용문·화자·본문과 사건의 출처 목록을 바꾸어 통과시키지 않습니다. 실제 소속을 확정할 수 없으면 이유를 남기고 연결 미확정 발언으로 보존합니다. 이미 올바른 사건 근거가 반환되면 기존 검토 경로를 유지합니다.
