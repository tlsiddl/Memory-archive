## 구현/범위
- runtime.js의 일반 발언 출력 계약에 eventSourceSegmentNumbers를 명시했습니다. 대사 근거와 사건 근거가 다르면 실제 사건 문단을 지정하도록 기존 설명과 출력 계약을 맞췄습니다.
- 일반 대조가 두 번의 기존 검토/재시도 후에도 사건 근거 오류로 멈추는 경우에만 ‘발언 사건 근거 선택’을 추가 실행합니다. 요청은 해당 오류 후보, 이미 반환된 항목, 대사 원문 및 각 실제 사건의 출처 문단을 제공합니다. 추출/독립 원문 대조를 처음부터 다시 실행하지 않습니다.
- bindDialogueEventEvidence는 요청한 후보 전부의 고유 번호·실제 eventNumber·그 사건 sourceIds에 속한 실제 문단 번호·이유를 검사합니다. 대사 쪽 문단을 사건 근거로 복사하거나 범위 밖/중복/누락 번호를 반환하면 거부합니다. 연결 사건을 달리 고르려면 제공된 실제 사건을 명시적으로 선택해야 합니다.
- 별도 선택 결과는 eventNumber/eventSourceSegmentNumbers만 갱신합니다. 인용문·화자·본문/기존 연결 설명·제외 제안 및 사건의 sourceIds를 그대로 보존하고, 다시 기존 mergeDialogueReview/validateDetailReview/applyExtraction 검사를 거칩니다. 원문/시간을 추측하거나 첫 사건에 임의로 연결하지 않습니다.
- 모델이 실제 사건을 확정하지 못하면 eventNumber:null, 빈 근거 목록 및 구체적인 이유로 연결 미확정 발언을 보존합니다. 발언 삭제/가짜 인물/사건 출처 확장으로 검증을 우회하지 않습니다. 선택 사유/전후 사건 번호/실제 문단은 dialogueEvidenceSelections 감사 이력에 보존합니다.
- 추가 근거 선택도 기존 qualityStage의 최대 두 번 검증/재시도 및 취소/오류 진단을 사용합니다. 틀린 선택이 반복되면 미완료 상태로 멈추고 기존 체크포인트/기억을 유지합니다. 이미 올바른 사건 근거가 제공된 대조는 추가 호출이 없습니다.
- 변경 파일은 runtime.js, runtime.test.cjs, build.py/README.md/RELEASE-NOTES.md입니다. core.cjs·기존 core/DOM·브라우저 테스트·UI/CSS는 변경하지 않습니다. 공개 API/이벤트·설정 키/기본값·저장 스키마·모델 연결/토큰/원문 묶음 크기를 변경하지 않습니다.

# v0.10.20 변경·검증 기록

## 기준/사전 분석과 재현
- 기준은 v0.10.19입니다. 해당 ZIP/source 전체를 verification-v01020/baseline-v01019에 보존했습니다. 기존 테스트를 수정 없이 현재 구현에서 별도로 실행합니다.
- 제공된 진단은 63개 중 62개 확인, 미확인 57번, 오류 항목 없음, 10회 한도 및 tailBudget:0이며 직전 모델 응답은 다시 49·51번 ‘네.’입니다. 이전 수정의 테스트는 일반 횟수 한도와 다른 원문 간 출처 보존을 확인했으나, 같은 원문/다른 화자/공통 ‘네.’ 및 재사용된 ref가 결합되는 조건은 놓쳤습니다.
- 실제 mergeDialogueReview에서 기존 발언의 화자가 다르더라도 새 인용의 이름표가 하나이면 초안 화자를 교정할 수 있는 조건이 있었습니다. 이미 검증된 발언에도 적용되어 서재헌의 ‘네.’를 직원의 ‘네. 아, 죄송한데…’로 덮었습니다. 새 긴 발언이 기존 짧은 발언 ref를 물려받은 뒤, 짧은 발언을 다시 추가하면 동일 생성 ref가 겹치고 후속 병합에서 긴 발언이 삭제됩니다.
- 수정 전/후 코드를 같은 63개 입력으로 실행했습니다. 같은 O8mPSVxOGsiDSvrypHUJb 안에 49·51번 서재헌 ‘네.’와 57번 직원 휴대폰 안내를 배치하면 v0.10.19의 미확인 후보가 [57] → [49,51] → [57] → [49,51] → [57]로 순환합니다. v0.10.20에서는 [57] → [] 후 두 화자를 모두 보존합니다. 직원의 실제 제공 문구와 합성 선행 발언을 사용한 코드 재현이며 사용자 방 전체 저장 초안을 그대로 읽은 것은 아닙니다.

## 구현/영향 범위
- core.cjs mergeDialogueReview: progressiveCoverage에서 이미 검증된 기존 발언의 화자는 새 발언의 이름표만으로 교정하지 않습니다. 서로 다른 확인된 화자의 기록을 병합하지 않습니다. 기존 실제 별칭의 canonicalName 대응과 아직 검증하지 않은 초안 화자의 원문 교정 및 기본 직접 호출 동작은 유지합니다.
- 새 발언 ref가 소비하지 않은 기존 기록과 충돌하면 기존 기록을 보존하고 새 발언에 겹치지 않는 ref를 부여합니다. 이전 버전에서 직원 발언이 짧은 응답 ref를 물려받은 체크포인트도 새 응답을 별도 ref로 추가할 수 있습니다. 충돌 처리 과정은 dialogue_ref_collision 감사 이력으로 보존합니다.
- runtime.js reviewedCandidate: 새 후보 확인으로 기존 확인 후보가 다시 누락되면 dialogue_coverage_regression으로 저장 전 중단하고 전후 미확인/새 확인/퇴행 후보 번호를 남깁니다. 이 상태를 정상 진행으로 세어 반복 요청하지 않습니다.
- 최종 대조 진입 조건은 재개 시 이미 확인한 후보도 진행으로 인정합니다. 이번 실행 시작 때의 미확인 개수보다 줄어야만 진입하던 조건을 수정했습니다. 1~16개 후보/진입 시 남은 개수의 고정 추가 예산, 일반 검토 횟수 및 진전 없는 응답의 기존 두 번 검증/재시도는 유지합니다.
- 변경은 위 core/runtime 연관 함수와 테스트·버전/문서에 한정합니다. UI/CSS·DOM/브라우저 테스트는 수정하지 않습니다. 데이터 초기화나 저장 스키마·설정 키/기본값·공개 API/이벤트·모델 연결/토큰/요청 제한 변경은 없습니다.

- 기존 기능 검사 311개를 별도 실행. core/DOM 이전 테스트는 원본 그대로 사용함. runtime은 새 모델 단계의 모의 응답을 추가하고 두 기대값만 변경함: 실제 발언 목록이 있는 수집에는 ‘발언·사건 대조’ 호출이 포함됨; 과거에는 빠져 있던 다음 응답의 정상 인용도 현재 구간에서 보존됨. 이전에는 없어야 한다고 가정했던 발언을 새 요구에 따라 보존하도록 바뀐 것이며, 기존 과거 참고 인용 검증은 유지함.
- 이전 ZIP/소스와 수정본 비교. 공개 export/설정 기본값 보존, Node 문법 검사, ZIP 압축 해제/필수 파일/소스와 번들 바이트/manifest 버전 외 동일 확인.

## 보존 및 한계
- 기존 사건/챕터/전체 수집·재수집/활성 요약/검색·주입/연결/중복 통합/인물/시간/백업·복원/되돌리기/모바일 컨트롤 유지. 자동 발언 단계가 실패해도 기존 기억을 교체하지 않음.
- 새 자동 단계는 대사가 있는 묶음에 추가 모델 호출을 사용하므로 시간과 비용이 늘어남. 기존 완료 구간을 업데이트만으로 자동 재수집하지 않음. 이미 저장된 방은 ‘발언 보강·사건 연결’로 교정할 수 있음.
- 실제 사용자 서버·실제 연결 모델의 분류/발화자/의미상 연결 판단·모바일/PC 브라우저·다른 확장과 동시 실행은 검증하지 못함. 모의 API와 DOM 검증을 실제 모델 성공으로 해석하면 안 됨. 후보 밖의 대사 발견과 의미상 올바른 사건 배정은 모델의 원문 독해가 필요함.
